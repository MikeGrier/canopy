| [CHECKLIST.md](CHECKLIST.md) (`LOCK-M1`) | 2026-08-22 | Gave a store root a cross-process writer lock (`D116`). canopy's single-writer guarantee was the `D41` monitor actor, which serializes writes only *within* one process; `D54`'s compare-and-set did not close the gap, because the digest read and the rename are separate steps, so two processes could both pass the precondition and one silently clobber the other. Exclusion is whole-root and writers-only (`D8`'s atomic rename already isolates readers), made of an OS advisory lock the kernel releases when the holder dies rather than a pid marker that would wedge the store, taken through the `Vfs` seam so the unacquirable-lock branch stays injectable, and reported as the named `StoreError::RootInUse`. Acquired in both `init` and `open`, released by the **last** `Store` clone. Proven by 9 unit tests plus 5 cross-process tests that spawn a real holder and kill it, on Windows **and** Linux. Raised while designing an engine-local metadata store for `gaffer`, the first consumer needing an exact value rather than a fast one. | [DESIGN-NOTES.md](../../DESIGN-NOTES.md) D116; [DESIGN-NOTES.md](DESIGN-NOTES.md) D8, D41, D53, D54 |

| [CHECKLIST.md](CHECKLIST.md) (`BG-M1`) | 2026-09-02 | Made `canopy` the hierarchical path store `D40`/`D54` specified but never got. What existed was a single path *component* with a shard prefix derived from that component's own characters -- undocumented drift that only surfaced when `D216`'s pending-work queue needed a `pending-work/<entry>` collection. Added a `NodePath` of validated components (64 chars each, 16 deep, 512 total -- the 64 pinned by a test because a `D4` idempotency key is a SHA-256 hex string of exactly that length), one directory per component on disk, and a child listing that costs `O(children)` rather than `O(store)`. Retired sharding entirely: it existed only to synthesize a directory tier from a flat name, so with real paths it has nothing left to do, and path structure became whatever a caller supplies. Enforced one namespace per level -- a name is either a document or a child node, never both. `GENESIS_FORMAT_VERSION` moved to 2 and a v1 store is refused rather than reinterpreted, since its shard tier would read as an ordinary path component. | [DESIGN-NOTES.md](../../DESIGN-NOTES.md) `D222`; [DESIGN-NOTES.md](DESIGN-NOTES.md) |
| [CHECKLIST.md](CHECKLIST.md) (`BG-M2`) | 2026-09-02 | Gave `canopy` the removal it never had, in the same breaking change as `BG-M1` because the format bump and call-site churn are paid once either way. A `Swap` now carries an `Effect` of `Write(body)` or `Remove`, so one transaction can mix them -- which `D216` needs, since a queue entry's removal must land atomically with whatever else the action changed. A document removal stages nothing, so it needs no rollback before `prepare` and no intent sidecar, and it is idempotent *by specification* because `D53` recovery replays a prepared transaction. Node removal is `rmdir`, non-recursive by construction rather than by intent, and joins the swap set: its emptiness precondition is judged against the node as the transaction will leave it, not as it stands -- the only post-transaction precondition in `D53`, and the only shape that admits the driving case of removing a node's last document and the node together. Soundness rests on `D116`'s single writer, which is what guarantees nothing changes the node between the phase-1 check and the phase-4 apply. | [DESIGN-NOTES.md](../../DESIGN-NOTES.md) `D222`; [DESIGN-NOTES.md](DESIGN-NOTES.md) |
